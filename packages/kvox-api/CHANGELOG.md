### Minor Changes

- 346b9c3: Add `@marinoscar/kvox-api/ask` and `/ask/testing`: `AskModule.forRoot` (saved conversations, the `ask.respond` job that drives `KVOX_AI.chat` with the seven read-only graph tools, and the SSE view over the durable answer) over the host ports and the graph, notes and search slices, with `AskUserDataService` and `describeAskConformance`, `createScriptedChat`, an in-memory copy of the two Ask tables and the tool fakes in the testing entry. The turn's caps (`limits.maxSteps`, `maxCallsPerStep`, `softClockMs`) can only be lowered by a host, and `forRoot` throws for a value above today's. `core` gains `KvoxRowStreamPoller`, the poll loop the note and Ask streams now share (the notes slice re-exports the constants it used to define). The `KVOX_AI` chat `done` event gains an optional `finishReason` (`stop`, `length`, `content_filter`), and the graph slice's AI run resolver accepts the `ask.respond` task.
- 44a612a: `describeKvoxPortsConformance` gains the optional object-store hook `uploadParts(init, size)` on `KvoxObjectStoreUnderTest`. The rule "the onUploaded handler fires once per completed upload" sealed an upload nothing had been sent to, which only an in-memory fake accepts: a store that checks its parts at `completeUpload` (the bare host's filesystem store, S3) refused it with `Part 1 of 1 has not been uploaded`. A host that supplies the hook has the kit PUT the bytes to the signed part URLs first; without it the rule behaves as before, so existing factories are unaffected. Found by running the kit against the bare host's local ports (`examples/bare-host/test/ports-conformance.test.ts`, now part of the `bare-host` CI job on both database legs).
- 44a612a: Export `KgMigrateEnqueuer` and `KG_MIGRATE_OWNERS_PER_TICK` from `@marinoscar/kvox-api/graph` (`@stability experimental`) and add the enqueuer to the exports of `GraphModule`. A host that sets `schedules: false` (KVox Desktop) can now drive the `kg.migrate` scheduler tick on its own timer by resolving the class from the container and calling `enqueue()`, the way it already calls the transcripts, notes and export-expiry enqueuers.
- ba8233b: `GraphRdfModule.forRoot({ shacl: { run } })`: a host whose binary cannot run Node as a child (KVox Desktop: Electron with the RunAsNode fuse off) runs the import's SHACL validation in an isolated process of its own. `run(input, { signal })` receives the JSON the default child reads on stdin and resolves with the report JSON; the import's timeout still applies. The new light entry `@marinoscar/kvox-api/graph-rdf/shacl-runner` exports `runShaclValidation(input): Promise<string>` (Node built-ins only, no Nest) for that process; it and the default child run one script, `runners/shacl-runner.cjs`, so the inline `-e` module is gone. Without `shacl.run` nothing changes (#586).
- 4a4b074: Add `@marinoscar/kvox-api/graph`, `/graph-extraction` and `/graph-rdf`, each with a `/testing` entry: `GraphModule.forRoot` (the single graph write path, the read layer, the access rules, the ontology and attribute services, the entity brief, the overview layout, the speaker link, `kg.migrate` and `kg.purge`), `GraphExtractionModule.forRoot` (`kg.extract`, `kg.resolve`, `kg.embed`, the proposal stages and the review-and-commit routes) and `GraphRdfModule.forRoot` (the OWL and SHACL artefacts, `kg.export`, `kg.import`) over the host ports and the transcripts, notes and search slices, with `describeGraphConformance`, `describeGraphExtractionConformance`, `describeGraphRdfConformance` and `GRAPH_PERMISSIONS`. The extraction subscribes to `kvox.notes.note_ready` on `KVOX_EVENTS` itself, so the notes slice never knows the graph exists. The ports gain, additively, `KVOX_JOBS.findLatest` and `runNow`, `KVOX_OBJECT_STORE.listManaged`, the `maxWait` transaction option, and, on `KVOX_AI`, the context `jobId`, the strict `jsonSchema` and `maxOutputTokens` of `generateStructured`, the error classes `truncated` and `invalid_output` and `KvoxAiError.usage`. `search` now exports `SEARCH_TRANSCRIPT_VISIBILITY` from its module. `graphology` (four packages), `n3`, `jsonld` and `rdf-validate-shacl` join the optional peers.
- a466697: Add `@marinoscar/kvox-api/notes`, `@marinoscar/kvox-api/notes/templates` and `@marinoscar/kvox-api/notes/testing`: `NotesModule.forRoot` (the note, template, document-source and generation-stream routes, the six job handlers, the access rules, the three exporters, the built-in templates with an idempotent `seedNoteTemplates`, and `NotesUserDataService`) over the host ports and the transcripts and search slices, with `describeNotesConformance`, `describeNoteExporterConformance` and `createNotesServiceTestFactory`. A ready note now publishes `kvox.notes.note_ready` on `KVOX_EVENTS` after its commit; the slice no longer knows the knowledge graph. The ports gain, additively, `KVOX_JOBS.enqueueWithin` and, on `KVOX_OBJECT_STORE`, `setMetadata` and the `ownerId`, `managedBy` and `metadata` fields of `describe`. `docx` and `unpdf` join `pdfkit` as optional peers. `@marinoscar/kvox-contract/notes` gains the `note.source.extract` node result schema and the ready event payload.
- a7eec64: Publish the host ports of the domain: `@marinoscar/kvox-api/ports` (the interfaces and `Symbol.for` tokens `KVOX_AI`, `KVOX_OBJECT_STORE`, `KVOX_JOBS`, `KVOX_IDENTITY`, `KVOX_NOTIFY`, `KVOX_EVENTS`, `KVOX_PRISMA`, `KVOX_SETTINGS`, `KVOX_SECRETS` and `KVOX_AUDIT`), `@marinoscar/kvox-api/core` (`KvoxPortsModule.forRoot`, `@KvoxAuth()`, `CurrentKvoxPrincipal`, `KvoxAuthGuard`, and the helpers the API's slices shared across each other: the per-user AI throttle key, the token budget, the stream flusher and SSE helpers, the ETag helpers, `KvoxEventEmitterEvents`, the `Prisma` SQL helper) and `@marinoscar/kvox-api/testing` (an in-memory fake of every port, `createKvoxTestingModule` and `describeKvoxPortsConformance`, which works under Jest and Vitest).
- 811db06: Add `@marinoscar/kvox-api/search` and `/search/testing`: `SearchModule.forRoot` (`GET /api/search`, the hybrid full-text and semantic ranking fused by reciprocal rank, snippets and cursors) and `SearchIndexingModule.forRoot` (the server-only `search.index` job, `SearchIndexService` with `enqueue` and `forget`, `GET /api/search/index-status` and `POST /api/search/index`) over the database, AI, jobs and identity ports, with a `SearchTranscriptVisibility` extension point for which transcripts a caller may see (the default is the owner's), configurable permission strings, a conformance kit (`describeSearchConformance`) and a fixture corpus (`seedSearchCorpus`) for the real-database test host. The routes declare no permission and narrow the searched types from the principal's `transcripts:read` and `notes:read`.

  When the host's AI port reports no embeddings model, or one whose vectors are not 1536 wide (the width of the index column), search answers with full text only and says so.

  `@marinoscar/kvox-contract/search` and `/errors`: `SEMANTIC_REASONS` and `KVOX_ERROR_CODES` gain `embeddings_unavailable` (added, never renamed); it is an additional value of the `semanticReason` enum in the generated API document.

- f74731e: Add `@marinoscar/kvox-api/transcription` and `/transcription/testing`: `TranscriptionModule.forRoot` (the provider registry, the AssemblyAI provider, the `transcription` settings namespace and secret purpose, and the admin settings and capability controllers) over the settings, secrets, identity and audit ports, with an open provider id vocabulary (`extraProviders`), configurable permission strings, a provider conformance kit and a scriptable fake provider. `core` gains `KvoxAuthFromOptions`, `KVOX_AUTH_PERMISSIONS` and `documentKvoxAuth` / `setKvoxAuthDocumenter`: `KvoxAuth` no longer attaches an OpenAPI marker itself, the owning module's `forRoot` does. `ports` gains optional members only (`readSystem` option `withUpdatedBy`, `set` option `label`, `updatedByUserId` on a secret's status, `KvoxRateLimitError` self-classification). The package gets a real-database test host (`npm run test:host:prepare`, `npm run test:db`).

  `@marinoscar/kvox-contract/transcription`: the `provider` of the `transcription` settings is any non-empty string (`transcriptionProviderIdSchema`) and `providers` accepts other providers' blocks; the generated API document is unchanged.

- b53e8e9: Add `@marinoscar/kvox-api/transcripts` and `@marinoscar/kvox-api/transcripts/testing`: `TranscriptsModule.forRoot` (the upload hook, the nine job handlers, the correction, export, name-check and share routes, the pure editing core, the access rules and the three exporters) over the host ports, with `TranscriptSharing` as the extension point for who else may open a transcript (owner-only by default), `describeTranscriptsConformance` and `describeTranscriptExporterConformance`. The ports gain, additively, `KVOX_JOBS.onSettled`, `findActive` and `tempPath`, `KVOX_OBJECT_STORE.adopt`, `describe`, `onAborted` and an `onUploaded` content-type filter, an idempotent `put`, `$transaction` options and an array form, `KVOX_AI.resolveTask` `requireKey`, and an optional `brand` on `KvoxPortsModule.forRoot`. `@marinoscar/kvox-contract/transcripts` gains the `media.audio.transcode` node result schema.
- 1d98ec7: Fixes found by the bare-host smoke app (`examples/bare-host`, a host that installs the packed tarballs and is not the web edition). `@marinoscar/kvox-db` gains the migration `20261016120000_transcripts_org_id` (byte for byte the web app's, which `kvox-db sync` adopts): the transcripts fragment already declared the NOT NULL `org_id` column, but a host with no domain history never got it, so no transcript could be created. `organizations` joins `users`, `storage_objects` and `jobs` as a host table a domain migration may reference (`KVOX_HOST_TABLES`, `KVOX_HOST_MODELS`). `@marinoscar/kvox-api`: resolving a provider a host registers through `extraProviders` no longer fails for want of a stored settings block; the PDF exporters' exported drawing helpers take the new `KvoxPdfDocument` type (an `object`, from `core`) instead of pdfkit's, so the package's declaration files typecheck with `skipLibCheck: false` in a host that left the optional `pdfkit` peer out; and the `ai` system settings namespace the slices read, the global `ZodValidationPipe` and the host's upload-completion route are documented as host duties.
- 45f8f99: Document how to consume the domain packages from a host that is not the web edition. Every package README and every slice README gains a `### Desktop` note that links the new KVox Desktop consumer guide (`docs/guides/kvox-desktop.md`): the packages and slices, the install lines and optional peers, the embedded database (PGlite or a bundled PostgreSQL, the `kvox-db sync --names after-host` prepare sequence), the ten ports to implement with their rules and the bare-host reference classes, a sketch of the GitHub Copilot SDK `KVOX_AI` adapter, the in-process job runner, the API and web wiring, what changes offline feature by feature, the conformance kits to run and the version policy. No code or contract changes.
- 26b224e: Manual relation edits (#586): `POST /api/graph/entities/:id/relations` sets a Person's manager (`REPORTS_TO`), employer (`WORKS_FOR`) or role (`HAS_ROLE`) by hand, closing the still-open edge of that type with the proposal commit's closing rule, and `DELETE /api/graph/entities/:id/relations/:relationId` retracts a wrong one. The relation is cited by the owner: a server-authored evidence row (`source.kind: 'manual'`, quote "Set by hand: …", the reserved `MANUAL_EVIDENCE_SOURCE_IRI` that `evidenceInputSchema` now refuses from any client), which Ask cites as a valid evidence citation labelled "Set by hand". The entity page offers "Set manager", "Set employer", "Add role" and Remove (`EntityRelationDialog`, `useEntityRelationEdits`), and a new `/graph/review` page (`GraphReviewPage`, `useGraphReviewQueue`) lists the proposals waiting for review. `@marinoscar/kvox-api/testing` gains the scenario-driven model hosts use in end-to-end tests (`createScenarioKvoxAi`, `scenarioStructuredAnswer`, `nextAskMove`, `KvoxScenarioMeeting`), moved from the bare host; `ruleForEffectiveRelation`, `isExclusiveTemporal` and `loadLiveTemporalEdges` are exported from the graph slice.
- 3ebe5c3: Import a Markdown note export back into a note (#585). `@marinoscar/kvox-contract/notes` adds `parseNoteMarkdownExport` (pure: the title, the body without the exporter's heading and provenance block, the body format and the export's provenance, or a typed refusal), the format identifier `NOTE_MARKDOWN_EXPORT_SCHEMA` (`kvox.note/v1`), the four `NOTE_IMPORT_FAILURE_REASONS` (also in `KVOX_ERROR_CODES`), the import response, and `detectKvoxImport` / `KVOX_IMPORT_ROUTES`, which decide from a file's first bytes which import route a host sends it to (transcript JSON, note export, or a PDF/text/Markdown note source). `@marinoscar/kvox-api/notes` adds `POST /api/notes/import` (multipart, `notes:write`, `maxImportBytes` option, 5 MiB default) and `NoteImportService`: a `ready` note with version 1 as an `edit` by the importer, the file kept as its source document with its extraction queued, the search index queued and `kvox.notes.note_ready` published; the Markdown exporter's front matter now opens with `schema: "kvox.note/v1"` and carries `bodyFormat`. `@marinoscar/kvox-web/notes` adds `importNoteMarkdown`, `NotesPage`'s `secondaryAction`, and `NewNotePage`'s `?objectId=` (with `?documentName=`), which pre-selects a document the host already uploaded. Every upload route (`POST /api/notes/import`, `/api/notes/sources/documents`, `/api/transcripts/imports`, `/api/graph/imports`) now answers 413 for a file `@fastify/multipart` hands back truncated at the size limit without throwing, instead of storing the first `fileSize` bytes as if they were the whole file.
- d38a85d: First pre-release of the KVox domain packages: empty, documented and buildable skeletons of the contract, db, api and web packages, with the `kvox-db` command printing its usage. The domain code moves in with Epic 5 and Epic 6.
- c029278: Import a `kvox.transcript/v1` JSON export as a transcript. `@marinoscar/kvox-contract/transcripts` adds the Zod mirror of the published schema (`transcriptDocumentV1Schema`), the import response and the six typed failure reasons (`TRANSCRIPT_IMPORT_FAILURE_REASONS`, also in `KVOX_ERROR_CODES`); the schema gains an optional, additive `transcript.recordedAt`. `@marinoscar/kvox-api/transcripts` adds `POST /api/transcripts/imports` (multipart, `transcripts:write`, `maxImportBytes` option, 25 MiB default) and `TranscriptImportService`, which writes the transcript, speakers, identities, segments and version 1 with no audio and no transcription job; the JSON exporter now emits `recordedAt`; the transcripts conformance kit gains a required `importer` target and two import invariants. `@marinoscar/kvox-web/transcripts` adds `importTranscript`, `ImportTranscriptButton` (an "Import transcript (JSON)" action on the library and new-transcript pages) and hides the player for an imported transcript; `LibraryPageFrame` gains an optional `secondaryAction`. The transcripts slice declares `@fastify/multipart` in `$hostPlugins` (a host without it gets a 500 naming the plugin on the import route).
- faaf3f8: The notes slice serves `GET /api/notes/sources/documents/{objectId}`, the extraction status of an uploaded source document (`notes:read`, owner-scoped, 404 for any id the caller does not own), with the new `noteSourceDocumentStatusResponseSchema` in `@marinoscar/kvox-contract/notes`. ### Patch Changes

- 510ce05: Fix the `relationTypes` description of the Ask `neighbors` tool: the example now uses the ontology relation `WORKS_FOR` instead of the nonexistent `WORKS_AT` (#570).
- 6033448: `kg.speaker_link` no longer deadlocks a one-connection database (PGlite with a single connection, as the desktop host runs it) (#612): the job resolves the owner's effective schema and `graph:write` permission before it opens its transaction, and `SpeakerLinkReconciler.reconcile(tx, input, context)` uses only `tx` (the context comes from the new `resolveContext(actorUserId)`).
- ff28dde: Reviewing and committing a proposal no longer deadlocks a one-connection database (PGlite with a single connection, as the desktop host runs it) (#615). A segment span's origin transcript is resolved before the review transaction opens (new `SpanValidator.prepare(source, spans)`; `validate(tx, source, spans, context)` uses only `tx`), and the commit prefetches the port answers its evidence checks need (import-object ownership, transcripts shared with the owner) before its transaction: new `EvidenceValidator.prefetch` / `GraphWriteService.prefetchEvidence` return an `EvidenceAccess` that `assertReadable`, `viewableTranscriptIds`, the create inputs (`evidenceAccess`) and `addEvidence` accept optionally. An owned transcript never asks the sharing port; an id the access does not cover still goes to the port, so other callers are unchanged.
- 381ad73: The ports conformance kit gains an opt-in `noDefaults` settings fixture (`KvoxNoDefaultsSettingsFixture`): a user namespace registered with `defaults: undefined` must read `undefined` before any write, without running its schema, and the parsed value after `patchUser`.
- 6e96e2c: Publish `graph.changed` after a proposal commit (`commit`, or `import` for an RDF import proposal), a revert, a manual merge and a merge reversal, once per action and only after the transaction commits, so the graph layout re-lays after material changes (#591).
- 596d2eb: Declare `@fastify/multipart` as a host plugin of the `notes` and `graph-rdf` slices (`$hostPlugins` in `kvox-slice-peers.json`, enforced by `check-slice-peers` rule 8), and answer a clear 500 from the document and RDF upload routes when the host has not registered it.
- 8dfebb9: Harness parity (#580). `@marinoscar/kvox-ai/testing` gains request recorders: `createRecordingRuntime` (every runtime round trip, without user, org, job or signal), `createRecordingAdapter` (a scripted provider adapter for `createDirectRuntime` that records what it receives) and `normalizeRecordedValue` (ids, timestamps and request ids numbered by first appearance, nothing dropped). `@marinoscar/kvox-eval/parity` drives notes generation, `kg.extract`, adjudication and three Ask questions through the real package code over any `KvoxAiPort` and ships the request snapshots (`parity/requests.*.json`) every host binding must reproduce; `kg` also exports `runExtraction` and `fixtureToInput`. `@marinoscar/kvox-api/notes` exports `budgetFromTarget` and the `AiTokenCaps` type.
- 35b405d: Carry `hasAudio` on the note origin transcript, proposal evidence and segment evidence links (false for an imported transcript), and hide playback in the notes and graph screens when it is false.
