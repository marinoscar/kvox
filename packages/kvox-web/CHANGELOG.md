# @marinoscar/kvox-web

## 0.1.0-next.0

### Minor Changes

- 45f8f99: Document how to consume the domain packages from a host that is not the web edition. Every package README and every slice README gains a `### Desktop` note that links the new KVox Desktop consumer guide (`docs/guides/kvox-desktop.md`): the packages and slices, the install lines and optional peers, the embedded database (PGlite or a bundled PostgreSQL, the `kvox-db sync --names after-host` prepare sequence), the ten ports to implement with their rules and the bare-host reference classes, a sketch of the GitHub Copilot SDK `KVOX_AI` adapter, the in-process job runner, the API and web wiring, what changes offline feature by feature, the conformance kits to run and the version policy. No code or contract changes.
- d38a85d: First pre-release of the KVox domain packages: empty, documented and buildable skeletons of the contract, db, api and web packages, with the `kvox-db` command printing its usage. The domain code moves in with Epic 5 and Epic 6.
- 0276d30: Add the `ask` slice: `@marinoscar/kvox-web/ask/headless` (the `/api/ask/**` client, the answer stream over `host.sse` with resume, the conversation hooks and the pure error-copy, citation and model helpers) and `@marinoscar/kvox-web/ask/ui` (`AskPage`, `AskThread`, `AskComposer`, `ConversationList`, `EntityAskPanel`, the `AskEntityButtonSlot` and `AskEntityPanelSlot` slot components for the graph entity page, and `kvoxAskRoutes`).
- 8ddd0c7: Add `@marinoscar/kvox-web/core/headless`, `/core/ui` and `/core/testing`, and `/transcription/headless` and `/transcription/ui`, replacing the empty `./core` scaffold entry. `core/headless` is the host port every web slice reads (`KvoxWebHost` with its HTTP, event-stream and optional upload transports, `KvoxWebHostProvider`, `useKvoxHost`, `useKvoxViewer`, `useHasPermission`), `KvoxApiError`, the `kvox*` request helpers, `connectKvoxSse` (reconnect with backoff and `Last-Event-ID` resume), the resumable upload engine, `useVisiblePolling`, and the domain-neutral hooks and helpers the slices share (relative time, the feed cache and reconciler, scroll restoration, the clipboard, the wake lock). `core/ui` carries the library chrome and the `KvoxSettingsCard`, `KvoxDestination` and `KvoxRouteDef` types a slice exports its settings cards, destinations and routes with. `core/testing` carries `createFakeKvoxWebHost`, `renderWithKvoxHost`, a fake `XMLHttpRequest` and `describeKvoxWebConformance`. The transcription slice moves the admin page, client and hook of `/admin/settings/transcription` into the package, with its card and route as data and a `renderSecretField` slot for the API key control. `@mui/material`, `@mui/icons-material`, `react-router-dom` and `@testing-library/react` stay optional peers: a host that uses only the headless entries installs none of them.
- b8ad94b: Add `@marinoscar/kvox-web/graph/headless`, `/graph/ui` and `/graph/testing`. The graph slice moves the connected-knowledge client (`/api/graph/**` and the `/api/ai-tasks/config` read), the entity, brief, timeline, mention, evidence, proposal, ontology, attribute-definition, preference, overview, export, import and extract-estimate hooks, the explorer and overview models, and the index, entity, explorer, overview, import and Knowledge graph settings pages into the package, over `KvoxWebHost` only (the preferences hook reads and writes `/api/user-settings` through the host with `If-Match` and one retry on a 409). The `knowledge` destination (gated on `graph:read` and the `graph` feature, owning `/graph` and `/ask`), its six routes and the Knowledge graph card are data (`kvoxGraphDestinations`, `kvoxGraphDestinationRoutes`, `kvoxGraphRoutes`, `kvoxGraphUserSettingsSections`). Ready-made slot components fill the transcript and note pages and both libraries (`graphTranscriptPageSlots`, `graphNotePageSlots`, `GraphSearchPrefix`), each returning nothing unless `host.features().graphEnabled` is on and the viewer holds the permission. The slice imports only `core`, `transcripts`, `notes` and `search`, never `ask`: the entity page takes the Ask action and panel as slots (`GraphEntityPageSlots`). `sigma`, `@react-sigma/core`, `graphology` and `graphology-layout-forceatlas2` are optional peers of `graph/ui` only; `GraphCanvas.tsx` is the one file that imports sigma and loads as a lazy chunk. `graph/testing` exports `mockGraphCanvas` for a host's tests, and `core/testing`'s fake host passes the caller's abort `signal` to a route.
- f58f6b3: Add `@marinoscar/kvox-web/notes/headless` and `/notes/ui`. The notes slice moves the four clients (`/api/notes/**`, `/api/note-templates/**`, note exports and the generation stream), the note, template, generation-context and template-preview hooks, and the library, new-note, note, history and note-template pages into the package, over `KvoxWebHost` only. The generation stream (`connectNoteStream`, `connectNoteGenerationStream`) runs over `host.sse` with the core reconnect loop and resumes with `Last-Event-ID`; every delta is still written at its offset, so a replay duplicates nothing. The `notes` destination, its routes (the four `/notes` paths and `/settings/note-templates`) and the Note Templates card are data (`kvoxNotesDestinations`, `kvoxNotesDestinationRoutes`, `kvoxNotesRoutes`, `kvoxNotesUserSettingsSections`). The slice imports only `core`, `transcripts` and `search`: the knowledge-graph features of the note page are slots the app fills (`NotePageSlots`: `Provider`, `useAsideWidth`, `HeaderActions`, `ProposalActions`, `SelectionActions`), as is the search-hits prefix of the library, each contained so a slot that throws renders nothing; the viewer's AI key and model list come in as the `ai` adapter (`NotesAiAccess`). `react-markdown`, `remark-gfm` and `@tiptap/*` are optional peers of `notes/ui` only, and the visual editor is loaded lazily. `core/ui` gains `KvoxCopyButton`.
- 102f163: Add `@marinoscar/kvox-web/search/headless` and `/search/ui`. The search slice moves the clients of `GET /api/search`, `GET /api/search/index-status` and `POST /api/search/index`, the `useSearch` and `useSearchIndex` hooks, `SearchResultsView`, `SearchSnippet`, `SemanticSearchNotice` and the Search Indexing page into the package, over `KvoxWebHost` only, with the page's card (`kvoxSearchUserSettingsSections`, no permission by design) and route (`kvoxSearchRoutes`) as data. `SemanticSearchNotice` explains the new `embeddings_unavailable` reason (a host without a usable embeddings model), and a test fails when the contract gains a reason without copy.
- 87f7bf5: Add `@marinoscar/kvox-web/transcripts/headless` and `/transcripts/ui`. The transcripts slice moves the six clients of `/api/transcripts/**` (reads, edits, versions, exports, name checks and the resumable upload sessions), the transcript, version, word, search, name-check, playback and source-audio hooks, the upload manager (`KvoxUploadManagerProvider`, mounted once at the app root) and the library, viewer, history and new-transcript pages into the package, over `KvoxWebHost` only, with the `transcripts` destination and the four routes as data (`kvoxTranscriptsDestinations`, `kvoxTranscriptsDestinationRoutes`, `kvoxTranscriptsRoutes`). The slice imports only `core`, `transcription` and `search`: the notes section, the speaker person links, the selection actions and the header actions of `TranscriptPage`, and the search-hits prefix of the library, are slots the app fills, each contained so a slot that throws renders nothing; sharing and AI availability come in as adapters. `KvoxWebHost` gains the optional `useLatestEventId` hook (a notification-stream fast path for list polling) and `KvoxRouteDef` gains `redirectTo`. `@tanstack/react-virtual` is an optional peer of `transcripts/ui`.

### Patch Changes

- 9140576: Rewrite the generated TSDoc of the `graph` slice (`@marinoscar/kvox-web/graph/headless` and `/graph/ui`) into specific descriptions: the wire types of the knowledge-graph client now say what each field means and when it is absent or `null`, the contract aliases name the values they carry, and the hooks, utilities, pages and component props describe what they do. Documentation only; no runtime code, type or export changes.
