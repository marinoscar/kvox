# graph

The connected-knowledge UI of `@marinoscar/kvox-web`: the knowledge index, the entity page, the explorer, the whole-graph overview, RDF import, the proposal review sheet and the Knowledge graph settings page, plus ready-made slot components for the transcript and note pages and both libraries.

## Purpose and scope

Everything a person does with their knowledge graph in the browser: list and search entities (`/graph`), read everything about one (`/graph/entities/:id`: the brief, the neighbourhood, connections, the timeline, mentions with evidence chips), edit or forget it, set a Person's manager, employer or role by hand, explore the graph from seeds (`/graph/explore`), see the whole graph by cluster (`/graph/overview`), review and import an RDF file (`/graph/imports/:proposalId`), see every proposal waiting for review (`/graph/review`), review the proposal a note or transcript produced (the review sheet, the extract dialog, "Add to graph" on a text selection), and set their own extraction preferences, domains and attribute definitions (`/settings/knowledge-graph`).

The headless half holds the API client (`/api/graph/**`, plus the `/api/ai-tasks/config` read the extract dialog needs), the hooks over it (`useGraphEntity`, `useGraphEntities`, `useGraphBrief`, `useGraphTimeline`, `useGraphMentions`, `useGraphEvidence`, `useGraphEvidenceFeed`, `useGraphOverview`, `useGraphProposal` (option `awaitUntil`; constants `PROPOSAL_POLL_MS`, `NOTE_EXTRACTION_FOLLOW_MS`), `useGraphReviewQueue`, `useEntityRelationEdits`, `useGraphOntology`, `useGraphEffectiveOntology`, `useGraphPreferences`, `useGraphAttributeDefs`, `useGraphExport`, `useGraphImport`, `useGraphExtractEstimate`, `useGraphTranscriptPeople`, `useGraphAiConfig`) and the pure helpers (display, spans, proposal grouping, explorer filters and hand-off, guidance, selection resolvers). The ui half holds the pages, the pieces other screens embed (`EvidenceChip`, `NeighborhoodWidget`, `EntityConnectionsList`, `EntityRelationDialog`, `SchemaForm`, `EntityTypeIcon`, `ProposalReviewSheet`), the explorer hook and models, the slot components, and the destination, routes and card as data.

The slice imports `core`, `transcripts`, `notes` and `search` and nothing from `ask`, which depends on it: the entity page's "Ask about this entity" action and panel come in as slots. The ontology is read from `@marinoscar/kvox-contract/ontology`.

Status: filled (Epic 7, issue 7.5).

## Entry point

- `@marinoscar/kvox-web/graph/headless`: the client (each call takes the host first), the hooks above, the preference types and defaults, the pure helpers and the wire types. No component, no `@mui/*`, no router, and none of the drawing libraries.
- `@marinoscar/kvox-web/graph/ui`: the seven pages (with `GraphReviewPage` and its `reviewTarget`), `EvidenceChip`, `NeighborhoodWidget`, `EntityConnectionsList`, `EntityRelationDialog` and `ENTITY_RELATION_EDITS`, `SchemaForm`, `EntityTypeIcon`, `entityPath`, `ProposalReviewSheet`, `useGraphExplorer`, the slot components and slot types, `kvoxGraphDestinations`, `kvoxGraphDestinationRoutes`, `kvoxGraphUserSettingsSections` and `kvoxGraphRoutes`.
- `@marinoscar/kvox-web/graph/testing`: `mockGraphCanvas`, the stand-in for the WebGL canvases. Test code only.

The app spreads `kvoxGraphDestinations` into its destination table directly after Notes, `kvoxGraphDestinationRoutes` into its ownership table, `kvoxGraphUserSettingsSections.knowledge` into a `Knowledge` group between `Account` and `Security`, and renders `kvoxGraphRoutes` where its literal graph routes used to be.

## Peer dependencies

`@marinoscar/kvox-contract`, `react` and `react-dom` for the headless entry. `ui` adds `@mui/material`, `@mui/icons-material` and `react-router-dom`, and the drawing libraries, all optional peers of the package and needed by this entry only: `sigma`, `@react-sigma/core`, `@sigma/node-image`, `@sigma/node-border`, `@sigma/edge-curve` (the pictograms, rings and curved edges; ranges compatible with sigma 3.0.x), `graphology`, `graphology-layout-forceatlas2` and `graphology-layout-noverlap`. `testing` needs only `react`.

Keep ONE copy of `graphology` in the host: sigma tests graphs with `instanceof`, so two copies draw nothing. `node scripts/kvox-packages/check-single-instance.mjs --guard graphology` checks it. The module-level hand-off between the overview and the explorer (`setExplorerHandoff`) is likewise per package copy, so a duplicated `@marinoscar/kvox-web` would lose it.

## Configuration

The hooks and pages read their host (`useKvoxHost`); there is no other configuration object. Host members that matter to this slice:

- `host.features().graphEnabled`: connected knowledge is on for this deployment. Every slot component returns nothing unless it is exactly `true`, and so does the Ask action of the entity page; `undefined` (not known yet) reads as off.
- `host.viewer()`: `graph:read` gates reading, `graph:write` the extract dialog, "Add to graph", import and the Knowledge graph page.
- `host.links.entity(id)`: where a speaker's person link goes.
- `host.http`: `/api/graph/**`, `/api/ai-tasks/config` (the models and the key notice of the extract dialog; `notes:read`) and `/api/user-settings` (the preferences of the Knowledge graph page: `GET`, and `PATCH` with `If-Match` carrying the document's version, retried once after a 409).

The 404-never-403 rule holds in the UI: an entity the API will not show answers "This page does not exist, or you no longer have access to it", never a permission message. `sensitive` person facts stay hidden unless the API returns them (`includeSensitive`); nothing is inferred client-side.

Permissions: `graph:read` opens every read route and the `knowledge` destination; `graph:write` gates the Knowledge graph page, import, the extract dialog, editing, forgetting and "Add to graph", and is checked again inside each control. The Knowledge graph card sets the user's `graph` settings namespace (`extraction`, `resolution`, `domains`) and their own attribute definitions; both are sparse, and a default is never written into the row.

UI: pages and components are MUI and need `react-router-dom`. The explorer, the overview and the entity page's neighbourhood widget draw with sigma, which is WebGL only: `GraphCanvas.tsx` is the one file that imports `sigma` and `@react-sigma/core`, and every screen reaches it through `React.lazy` (`canvasLoaders`), so a screen that never draws a graph never downloads either library, and the list view of the explorer and overview does not either. Without WebGL (`isWebGLAvailable`) the explorer and the overview force their list view and the widget hides itself. The destination's runtime-flag gate (`feature: 'graph'`) is the app shell's: the row is hidden while the switch is unknown. Pixels, markup and accessible names are unchanged by the move.

The explorer shell (GIC-08, #669): `GraphExplorerPage` renders through `InsightCanvasLayout` (`ui/components/explorer/shell/`), one component tree with the slots `topBar`, `facets`, `canvas`, `inspector` and `timeBar` that every panel of the Insight Canvas plugs into. It lives inside the page `<main>`, reads its own window classes (`useWindowClass`: compact below 600, medium 600 to 1199, expanded from 1200; 600 equals the platform `sm` gate by design, and none of the five platform shell gates changes) and the input modality (`useInputModality`: `(pointer: coarse)` or `(hover: none)`, independent of the width), and never remounts the canvas on a class change, so a rotation keeps the camera, the selection and the inspector. Compact: the inspector is a `BottomSheet` (peek 25%, half, full; drag, tap, arrow keys, Escape; a `region` at peek and half, a `dialog` at full) and the facets a drawer behind a Filters button. Medium: `FacetsRail` (56px icon chips opening popovers) and a closable 360px right overlay; the canvas pans the selection clear of it (`revealInsets`). Expanded: three panes with `role="separator"` resizers (arrow keys, Home and End), widths and collapse persisted per user and window class (`paneStorage.ts`, every storage access in `try/catch`). Touch: first tap previews a node, second opens the inspector, a 500ms long-press opens the node menu (`ExplorerContextMenu`) and arms dragging, "Select" mode marks nodes, `touch-action: none` is on the canvas alone and a coarse pointer picks within 22px of a node. `explorerBudgets` is the one place of the performance budgets (120 nodes on a compact window or coarse pointer, else 300; layout time box 1.5s or 3s; `devicePixelRatio` cap 2; `hideEdgesOnMove` above 500 or 1,000 edges; reduced label density); later stories read it instead of inventing their own. On a compact window a graph over 120 nodes opens as the list (`?view=graph` overrides). The inspector content is `ExplorerInspector` (GIC-11, below). The shell is verified at 390x844, 820x1180, 1180x820 and 1440x900 by `tests/visual/specs/graph-explorer.spec.ts`.

Data: the slice has no storage of its own. The module-level caches are per package copy and per page load: the effective ontology (`useGraphOntology`, dropped with `invalidateGraphOntology`), the evidence links (`useGraphEvidence`, dropped with `clearEvidenceCache`) and the explorer hand-off between the overview and the explorer. Every server fact is read through `host.http`.

## Extension-point catalog

- `GraphEntityPageSlots` (prop `slots` of `GraphEntityPage`): `AskButton` (`{ entityId, entityLabel, onClick }`, drawn in the entity header) and `AskPanel` (`{ entityId, entityLabel, entityType, open, onClose, conversationId, onConversationChange }`, the panel it opens). The page keeps the `?ask=` search parameter (open state and conversation), so a reload reopens the conversation and the back gesture closes the panel. Both render only while `graphEnabled` is `true`.
- `GraphExplorerPageSlots` (prop `slots` of `GraphExplorerPage`, GIC-11): `AskPanel` (the entity page's own `AskPanel` slot type, `GraphEntityAskPanelProps`) fills the inspector's Ask tab for a selected entity, rendered only while `graphEnabled` is `true`, so the slice takes no dependency on the ask slice; without it the tab does not exist. `NodeActions` (`{ nodeId }`) is the third primary action of a selected node (the home of "Path to…", GIC-13). The web edition passes the ask slice's `AskEntityPanelSlot` (`apps/web/src/kvox/GraphExplorerPageWithSlots.tsx`); KVox Desktop gets it by bumping the package pins and wiring the same wrapper.
- `graphTranscriptPageSlots`: the `useSpeakerPeople` (`useGraphSpeakerPeople`: speakers that are a person in the graph get an "Open the person's page" link) and `SelectionActions` (`GraphTranscriptSelectionActions`: "Add to graph" from a selection within one line, `graph:write`) members of the transcript page's slots, to spread next to the host's `NotesSection`. `graphTranscriptsLibrarySlots`: `SearchPrefix`, entity hits above the ranked results.
- `graphNotePageSlots`: every member of the note page's slots. `GraphNotePageProvider` holds the proposal and the open state of the review sheet and the extract dialog once for the page, opens the sheet for `?review=1` and then drops the parameter (its `ready` prop, default `true`, lets a host whose switch loads asynchronously hold that until it has); when the note turns `ready` (or the page opens within `NOTE_EXTRACTION_FOLLOW_MS`, 30 s, of it) it keeps re-reading the proposal for that window, through `useGraphProposal`'s `awaitUntil` option, so an automatic extraction appears without a reload); `useGraphNoteAsideWidth` makes room for the sheet at `lg` and up; `GraphNoteHeaderActions` is the review button with its undecided count; `GraphNoteProposalActions` is the sheet and the extract dialog; `GraphNoteSelectionActions` is "Add to graph" on the rendered body. `graphNotesLibrarySlots`: `SearchPrefix` for the notes library; `GraphSearchPrefix` is the component behind both.
- Every slot component returns `null` when connected knowledge is off or the viewer lacks the permission, so a host wires them unconditionally.
- `kvoxGraphDestinations`: one destination, `knowledge` ("Knowledge" for both labels, the hub icon, `/graph`, `graph:read`, `feature: 'graph'`, not pinned). With the switch off or unknown the row is hidden, never shown and then removed. `kvoxGraphDestinationRoutes`: its ownership prefixes `/graph` and `/ask`; the ask slice adds routes under it, never a fifth bottom-bar destination (four non-pinned tabs is the ceiling).
- `kvoxGraphUserSettingsSections.knowledge`: the Knowledge graph card, with `permission: 'graph:write'`, the exact string the attribute-definition write routes enforce.
- `kvoxGraphRoutes`: `/graph`, `/graph/entities/:id`, `/graph/explore`, `/graph/overview`, `/graph/review` on `graph:read` (a viewer without it is sent home), `/graph/imports/:proposalId` on `graph:write` (sent to `/graph`) and `/settings/knowledge-graph` on `graph:write` (sent to `/settings`). The pages are lazy; the entity page takes slots, so an app that offers Ask replaces its `Component` (the web edition does, in `apps/web/src/kvox/graphRoutes.ts`).
- Working example: the web edition wires the slots in `apps/web/src/kvox/` (`noteSlots.tsx`: the AI provider in front of `GraphNotePageProvider`; `transcriptSlots.tsx`; `GraphEntityPageWithSlots.tsx`, which passes the ask slice's `AskEntityButtonSlot` and `AskEntityPanelSlot`; `graphRoutes.ts`).

### Explorer layout (#668)

`GraphCanvas` lays the graph out with `layout/` (next to `GraphCanvas.tsx`), not on its render thread:

- **Worker.** `layout/layout.worker.ts` is a same-origin MODULE worker, built with `new Worker(new URL('./layout.worker.js', import.meta.url), { type: 'module' })` in `layout/layoutClient.ts`, so Vite and electron-vite emit it as its own file and `worker-src 'self'` allows it. Never a `blob:` URL (`graphology-layout-forceatlas2/worker` builds one). It runs ForceAtlas2 in fixed chunks, then `graphology-layout-noverlap`, and posts transferable `Float32Array` frames. Without `Worker`, or if the worker errors, `layoutEngine.ts` runs on the main thread in 8 ms slices per animation frame; the result is the same for a run that is not cut short by its time box.
- **Incremental.** After an expand only nodes never laid out move (they are ringed around their parent by `explorerModel`); every other node is `fixed`. "Re-layout all" in the Layout menu moves every unpinned node.
- **Layouts.** `?layout=force` (Force), `concentric` (rings by hop from the seeds, ordered by a node's `doi` attribute when present, otherwise by `degree`) and `static` (visual tests). With no parameter an ego view of fewer than 40 nodes opens concentric, otherwise Force, decided once.
- **Pins.** A dragged node, or the selected node with `P`, is pinned; pins persist per view in `sessionStorage` (`kvox.graph.pins:<view>`) and are released with `P` or "Unpin all".
- **Motion.** Positions tween over 300 ms; under `prefers-reduced-motion` only the final picture is shown, in one jump.
- **Budgets.** The layout time box is `shell/explorerBudgets.ts`' `layoutTimeBoxMs` (1.5 s compact or coarse pointer, 3 s otherwise); `layout/layoutBudgets.ts` keeps only the tuning constants.

### Evidence-first inspector (GIC-11, #672, epic #661)

`ExplorerInspector` (`ui/components/explorer/inspector/`) is the `inspector` slot's content in every window class; it reads no breakpoint (the page hands it the shell's window class and input modality, and `useOptionalInsightCanvas` gives it the sheet's snap). Pure rules are in `inspectorModel.ts`.

- **Node**: type glyph, label, type chip, up to three aliases then `+N`, "First seen · Last seen · N mentions", and the actions Focus (make seed), Expand (a split button: all neighbours, or its menu), Open page, Pin, Hide and Ask. Tabs, in the ARIA tabs pattern (MUI `Tabs`, `aria-controls`/`aria-labelledby` pairs): Overview (the entity brief, read with `markViewed: false` because selecting is not opening the page), Evidence, Connections, Timeline, and Ask (only with the `AskPanel` slot). An item (commitment, decision, claim) has Overview, Evidence and Connections. A node opens on Overview, an edge on Evidence.
- **Edge**: relation label, `A → B`, role, stage and stance chips, validity, confidence and the evidence count; tabs Evidence (default) and Overview (the relation's props and its two ends).
- **Evidence** (`useGraphEvidenceFeed`, `EvidenceCard`): an edge or item reads `GET /graph/evidence/by-subject?kind=&id=` (newest source first, at most 50); an entity reads that for its own citations, then the `evidenceIds` of its timeline pages, resolved with `GET /graph/evidence?ids=` in windows of at most 50. Twenty cards show at a time. A card is an `article` named "source title, date" with the quote (two lines clamped, "Show more", on an expanded window), the source kind and title, `Source unavailable` and `Text changed` / `Note edited since` badges, and "Open at source", the API's own `href`. The quote is shown even when the source is gone. **A person fact is never asked about**: the model gives a person-fact node or an edge touching one no evidence subject, the timeline is read without `includeSensitive`, a timeline event whose item is `sensitive` is dropped as well, and the API answers the item 404 for a sensitive item.
- **Connections**: the neighbours on the canvas grouped by relation type, each group with "N of M" (`counts.relationsByType`), "Show on canvas" (rings the group with the canvas's marked rings) and "Expand" (the rest of that relation), role and stance chips on each row.
- **Expand by type**: the split button's menu lists relation types (`counts.relationsByType`) and entity types (`counts.relationsByNeighborType`) with counts; `expand(id, { relationTypes | types })` sends only that, intersected with the filters in force (a type or relation the user hid sends nothing). The "+N more" stubs use the same path (`types: [stubType]`).
- **Selection view**: two or more marked nodes (Select mode) show counts by type, up to five shared neighbours, Expand all (one request after the other) and Hide (seeds stay). `selectionExtraActions` is where "Find connections" (GIC-14) and "Ask about selection" (GIC-17) plug in.
- **URL state**: `?sel=n:<nodeId>` or `?sel=e:<edgeId>` and `?tab=` (`useInspectorUrlState`), written with `replace`. On load the selection is restored once the graph has arrived and contains it, so Back from "Open at source" lands on the same seeds, selection and tab. Nodes reached by an expand are not in the URL; they reappear only if they are neighbours of a seed.
- **Compact**: at the sheet's peek only the header, three primary actions (Focus, Expand, and `NodeActions` or Open page) and "N evidence" show, with Pin, Hide and Ask behind `⋯`; the scrollable tab strip starts at half height. A coarse pointer gets 44px targets (48px tabs).
- **Slots left for later stories**: `selectionExtraActions` ("Find connections", "Ask about selection"), "show in TimeBar" on the Timeline tab (GIC-15).

### Path mode, "Connect A and B" (GIC-13, #674, epic #661)

Everything lives in `ui/components/explorer/paths/`; the page only wires slots through `usePathMode`. Pure rules (strength, hops, the screen-reader sentence, the URL) are in `pathModel.ts`.

- **URL**: `?pathFrom=<id>&pathTo=<id>` (+ `pathHops` 2 to 5, default 4 left out; `pathRel` a comma-separated list of relation types). A reload restores the search; `?pathFrom=` alone opens the picker with A filled in. A link with a path but no `?seed=` seeds the canvas from `pathFrom`.
- **Entry points**: the top bar's Connect button; "Path to…" in the inspector (`usePathMode().pathToAction`, drawn before the host's `NodeActions`); the node context menu (`extraItems`); and `openPicker(fromId?)`. **The command palette and the Start-here card are not on `main` yet** (#670): they wire in by calling `openPicker()` (the palette's "Connect A and B…" action, and the card's `onConnect`), or by navigating to `?pathFrom=`.
- **Search and strength**: `useGraphPaths` asks `GET /graph/paths` for `k=3` with the canvas's `as of` date. The API's `score` (mean `log(1 + evidenceCount)`, discounted for hubs) reads "strong evidence" from 1.5, "moderate" from 0.8, otherwise "weak" (`STRONG_PATH_SCORE`, `MODERATE_PATH_SCORE`).
- **Quotes**: `useHopQuotes` reads `GET /graph/evidence/by-subject` once per distinct edge (the newest citation whose source still exists), the call the Evidence tab makes. A person-fact hop gets no subject and is never asked; a virtual edge asks about its item.
- **Show on canvas**: merges the chosen path's nodes and edges (`useGraphExplorer().mergeExternalSlice`, never past the node cap; a notice says how many nodes did not fit), then `pathNodeIds`/`pathEdgeIds` make `explorerReducers` light the path and dim everything else (a hover or tap focus takes over), and `GraphCanvasControls.fitTo(ids)` frames it. Switching paths while one is shown redraws.
- **Where it lives**: compact, a vertical strip inside the bottom sheet (a full-screen picker; "Show on canvas" closes the sheet, and the top bar button brings it back); medium, a horizontal scroll-snap overlay on the canvas above the TimeBar slot, clear of the inspector overlay; expanded, the same overlay docked at the bottom and collapsible; list view, the panel above the list. No breakpoint is read here: the page hands in the shell's window class.
- **Keyboard and screen reader**: Tab walks the hops (a hop button, its quote's source link, "N more"); Enter on a hop selects that edge in the inspector on its Evidence tab (merging the path first if the edge is not on the canvas). A hop's name is a sentence, "Joe Rivera, involved in as stakeholder, skeptical, Copilot rollout", and the list is named by the whole path.
- **Not offered**: "Explain this path". The host's `AskPanel` takes an entity (`GraphEntityAskPanelProps`), not scoped evidence, and the API has no scoped context for Ask yet; a button that asked about one end would answer from the wrong evidence.

### Manual relation edits (#586)

On the entity page of a Person, for a caller with `graph:write`, the Connections section (`EntityConnectionsList`, props `entityType`, `canEdit`, `onChanged`) offers three buttons, "Set manager" (`REPORTS_TO` → Person), "Set employer" (`WORKS_FOR` → Organization) and "Add role" (`HAS_ROLE` → Organization). Each opens `EntityRelationDialog`, titled with the action: a combobox over the caller's own graph named "Manager", "Employer" or "Organization" (`EntitySearchField`, filtered to the allowed type), for a role the text boxes "Title" (required) and "Business unit", an optional date box "Since" (empty means today), and "Cancel" / "Save". Each stored outgoing manager, employer or role row has a button named "Remove <group> <label>" (for example "Remove Reports to Mark Chen") that opens "Remove this connection?" with "Cancel" / "Remove". A save or removal shows "Saved." or "Removed." in a status alert and re-reads the list, the neighbourhood canvas and the brief. The server closes the earlier open edge of the same kind at the new date and cites the relation "Set by hand"; the evidence chip names such a citation "Set by hand". Headless: `setEntityRelation`, `removeEntityRelation` and `useEntityRelationEdits(entityId)` (`{ setRelation, removeRelation, isSaving, error, clearError }`).

### Explorer visual language (#667, epic #661)

The canvas encodes a node's type three ways, never by colour alone: a fill colour, a bundled pictogram, and (in the legend) a label. `explorerEncoding.ts` is the pure rule book: a fixed, validated categorical palette (`CATEGORICAL_PALETTE`, 14 slots, a light and a dark variant chosen by the theme's `palette.mode`; checked for 3:1 contrast on both canvas backgrounds and for distinctness under simulated deuteranopia by `test/graph/explorerEncoding.test.ts`), `encodingFor(type, mode)` (an explicit entry for `Person`, `Organization`, `Project`, `Meeting`, `Topic`, `Product`, `Commitment`, `Decision`, `Risk`, `Claim`, `Interest`, `Trip` and `Milestone`, so the planned `Topic`, `Product` and `Risk` (#662 to #664) are encoded the day they land; any other key, a user type included, takes a hashed palette colour and the generic pictogram), node size (`6 + 1.6·√n`, `n` = `mentionCount`, else `degree`), rings, edge width (`1 + 1.1·ln(1 + evidenceCount)`, else from `confidence`: both are read defensively, so the code works before #671 adds `evidenceCount` and `mentionCount`), the `INVOLVED_IN` stance accent (champion green, supportive teal, neutral grey, skeptical amber, resistant red) and the curvature that fans parallel edges apart.

The pictograms are `icons/pictograms.ts`: path data (Material Icons geometry, Apache 2.0) turned into `data:image/svg+xml;base64,…` URLs, so there is no remote asset and no `.svg` file for `tsc` to miss. Base64 is deliberate: `@sigma/node-image` `fetch()`es a source whose path ends in `.svg`, which the production `connect-src` refuses for `data:`; a base64 body takes its plain-`Image` path, which `img-src data:` allows.

`GraphCanvas` draws a node as a ring-and-disc (`@sigma/node-border`) with the glyph on top (`@sigma/node-image`, pictogram mode), and parallel edges as curves (`@sigma/edge-curve`). The programs are chosen per node and edge by the reducers (`explorerReducers.ts`, pure): a graph without pictograms or curvature (the overview) draws as before. View state (hover, first tap, selection, rings, labels) lives in the reducers only, never in the graph's attributes: with a focus (hover, else first tap on a `(hover: none)` screen, else the selection) the node, its neighbours and the edges between them are lit and labelled and the rest keeps 15% opacity; only the focus's own edges, and a hovered edge, show a label. Rings: seed thick, selected thin, pinned thin set off by a gap (a WebGL node program cannot dash, so the "dashed" ring is a detached one). Not yet drawn dashed: derived edges and the `resistant` stance carry `dashed: true` on the edge, but sigma's edge programs have no dash; derived edges are drawn at 60% opacity, and the stance is also in the edge label.

Degree of interest (`degreeOfInterest`, `DOI_WEIGHTS`) ranks nodes: `ln(1 + mentionCount|degree)`, recency (halves every 90 days), seed/pinned/searched interest, minus hops from the seed. It orders truncation at the cap, the keyboard (`keyboardOrder`), and which neighbours a first open shows: at most `EXPLORER_NEIGHBOUR_LIMIT` (30) new ones, the rest one "+N more" stub per parent and type (`useGraphExplorer().expand(stubId)` expands it with `types: [that type]`; activating a stub on the canvas, or its row in the list, does that). A stub is a graph node (`isStub`) but not a real one: it is outside the node cap and the "N of 300" count of real nodes (`realNodeCount`).

`GraphLegend` is a standalone component; `GraphExplorerPage` places it in the shell's `facets` slot under the filters (the compact drawer, the medium popover, the expanded left pane) and wires its rows to the page's own `types` toggle: a list of toggle buttons with `aria-pressed`, the count as the description, a relation section and the stance key. `useLegendTypeFilter` is the same `types` round-trip for a host that places the legend itself. The canvas takes the input modality from the shell (`inputModality`, the single source) and the first-tap preview from the page (`previewId`); the node cap that degree-of-interest truncation runs into is the budget's (`explorerBudgets`: 120 or 300), carried as `ExplorerState.cap`. Re-enabling a type or relation filter refetches what the filter removed (the seeds and expanded nodes are expanded again and merged in; nothing moves).

### Review (`/graph/review`)

`GraphReviewPage` lists the caller's draft proposals (`useGraphReviewQueue`: `GET /api/graph/proposals?status=draft`, 20 at a time, "Load more"): a heading "Review", then one link per proposal named after its source with the rows still to decide and in total. A note extraction links to `host.links.note(noteId)` + `?review=1` (the note page opens its review sheet), an import to `/graph/imports/:id`; a `resolution` proposal has no review page and is not listed. Nothing waiting reads "Nothing to review". The index page links to it next to Explore and Overview.

Security notes: no HTML is injected: evidence quotes, labels and AI-written text render as React text. A forget request carries the typed confirmation (`FORGET_CONFIRMATION`) and the dialog makes the person type the person's name first. `sensitive` person facts are shown only when the API returns them, and never exported or bulk-accepted from here. A 404 from the API is shown as "not found", never as a permission error, so a foreign id leaks nothing. Testing: the slice is tested against `createFakeKvoxWebHost` from `@marinoscar/kvox-web/core/testing`, and `mockGraphCanvas` from `@marinoscar/kvox-web/graph/testing` stands in for the canvases.

### Desktop
