# apps/cli rules

Root rules ([AGENTS.md](../../AGENTS.md)) apply. This file is what to get right when editing the `kvox` CLI. Usage, install, flags, environment variables and CI setup: [README.md](README.md), the source of truth; do not restate it elsewhere.

## Layout

- The engine is **`@marinoscar/platform-cli`** (pinned in `package.json`): the `init`, `login`, `api`, `config`, `node` and `deploy` commands, the ink TUI, the VPS deploy pipeline and the worker-node engine. `src/` holds only what the platform does not have; **never add a copy of an engine file** (`app.test.ts` fails on one).
- `src/app.ts`: `APP_CLI_OPTIONS` (identity from `@app/shared`, `readVersion()`, node executors, proxy stream paths). `src/cli.ts`: the entry point. `src/run.ts`: one invocation (legacy flag translation, `update --check`, then `createCli(...).run`).
- `src/executors/`: the node executor for `media.audio.transcode` (+ its `ffmpeg`/`ffprobe` requirement, registered at module scope). `src/extensions/`: the pre-platform `deploy` flags and commands the platform lacks (`legacy-flags.ts` is the table), `update --check`, the `uninstall --confirm` guard and `.env` backup.
- The CLI is a workspace package (`--workspace=cli`), built from this monorepo and not published. CLI environment variables take the `KVOX_` prefix; API-side variables never do. The prefix, `~/.kvox/` and the systemd unit derive from `cliName` in `packages/shared/identity.json`.
- Extend the CLI through the platform's registries (`extraCommands`, `deploySteps`, `deployChecks`, `nodeExecutors`, `proxy.streamPaths`), not by editing a platform file: the package README (`node_modules/@marinoscar/platform-cli/README.md`). A `deploy` flag the platform lacks cannot be added to its command; it goes through `extensions/legacy-flags.ts` (ignore, alias, port or refuse, never silently accept).

## Version bump (root rule: CLI Version Bump on Improvement)

- The version lives **only** in `apps/cli/package.json` (today `1.10.1`). `readVersion()` in `src/app.ts` reads it at runtime; never hardcode it or import `package.json` elsewhere (see its comment).
- The version is recorded as `appctlVersion` in a deployment's state file, as `deployedBy.version` in `deploy-info/info.json`, and sent as the User-Agent on every API request. A stale version makes two installs indistinguishable in a deployment record.
- PATCH for an improvement or a set shipped together; MINOR for a new command or subcommand; **one bump per PR**. Then `npm install --package-lock-only` (the lockfile's `apps/cli` entry carries the version).
- Applies to `apps/cli`, `install.sh` and `apps/cli/bootstrap-vps.sh`. Adding only docs such as this file is not a CLI improvement.

## Deploying to a VPS

VPS deployment lives entirely in this CLI (the platform's pipeline) as `kvox deploy doctor|install|uninstall|update|status|about|list|certs`. There is no separate deploy script or Ansible playbook, and there should not be. The deploy state file `.appctl-deploy.json` and the proxy sentinel `# Managed by appctl deploy` are the platform's fixed literals: live servers carry them, never rename them.

- Command reference: [README.md#deploying-to-a-server](README.md#deploying-to-a-server); worker nodes: [README.md#running-a-worker-node](README.md#running-a-worker-node).
- Design, `deploy-info/info.json` schema, what `uninstall` refuses to remove (shared `devnet` network, shared proxy, TLS certificates), and how `update` adopts a deployment with no state file: [docs/specs/vps-deploy.md](../../docs/specs/vps-deploy.md) §18, §19, §21, §23 (written for the pre-platform engine; the README's "Flags and commands that changed" table says where it differs). Operator runbook: [docs/deployment/vps.md](../../docs/deployment/vps.md). Extend those instead of restating them.
- Worker nodes: [docs/specs/worker-nodes.md](../../docs/specs/worker-nodes.md), [docs/deployment/worker-nodes.md](../../docs/deployment/worker-nodes.md).

## Rules

- **`parseEnvExample` reads any commented `# KEY=value` line** in `infra/compose/.env.example` as a declared optional variable. `.env.example` is generated by `npm run platform:infra:sync` (platform variables, then `infra/compose/app.env.example`, this app's own): add a variable to `app.env.example`, uncommented with its default, never an illustrative commented assignment. The commented ones present come from the platform and are listed in `src/conformance.test.ts`; a new one fails the platform's `cli` conformance suite.
- A node never persists a job-scoped credential (root queue rule 3); only its own `nod_` identity token is stored.
- Server-only artifacts (exports, PDFs) are rendered by the API, never by the CLI; a second copy would diverge.
- A behaviour change carries tests in the same or the next commit.

Run: `npm run test:run --workspace=cli`, `npm run typecheck --workspace=cli`. `src/conformance.test.ts` runs the platform's CLI conformance (env fragments, executor credential hygiene, deploy registrations); add a new executor to it by registering it in `app.ts`.
