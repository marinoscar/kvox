Every date the API derives from an instant or from "now" now follows the user's time zone. `KvoxSettingsPort` gains `readUserTimeZone(userId)` (the web edition answers the profile zone, KVox Desktop the device zone); `@marinoscar/platform-contract` becomes a required peer of `@marinoscar/kvox-api`, which may import exactly its pure `timezone` entry. The Ask prompt states the asker's local date, weekday, time and zone (captured at enqueue as `timeZone` in the `ask.respond` payload) and Ask tools show instants as the asker's local day; the extraction meeting date is the owner's local day; note exports print "saved", "Exported" and the source date in the requester's zone with its name, and note exports (and PDF transcript exports, whose cover is dated by the recording) carry the zone in their content address; the graph activity buckets are cut in the requester's zone (`timeZone` in the response, DST-correct, weeks start Monday locally); a bare `since`, `from` or `to` over an instant column is local midnight in the requester's zone while a bare `as_of` and every calendar value stay floating dates; a relation set without `validFrom` starts on the requester's today; the import batch label uses the local day and the review-queue group key carries the batch `createdAt`; graph insights sentences and the graph export file name use the requester's or owner's day. The API reads the request zone from the `X-Time-Zone` header when the user has none stored. `graphExportFilename` takes an optional IANA zone.
