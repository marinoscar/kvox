Add `@marinoscar/kvox-web/shell`: the KVox app shell every host renders. It exports `KvoxAppShell` (the platform's shell with the KVox brand lockup, the rail, the phone bar and the user menu; host facts come in as `navigation`, `actions`, `banners`, `overlays`, `userMenuItems`, `renderUserMenuItems` and `showThemeToggle`), `createKvoxNavigation` (the destinations the slices declare, composed with the host's own, with the route ownership that lights exactly one row; it also returns the phone-bar twin, and `withoutPinned` builds it for any navigation), `renderKvoxRoutes` (a slice's route data as `<Route>` elements behind the platform's permission guard, with an optional `fallback`), `defaultKvoxLinks` (the `KvoxWebHost.links` of both hosts) and `AiKeyRequired` (the shared "add your key" state; the host passes `settingsPath` and may pass `providerName`). The shell reads no breakpoint and makes no request, so it renders in a local single-user host under the platform's `LocalIdentityProvider` and `ShellPreferencesProvider`. The `graph/ui`, `ask/ui` and `notes/ui` entries gain the Review (`kvoxReviewDestinations`), Ask (`kvoxAskDestinations`) and Templates (`kvoxNoteTemplatesDestinations`) destinations with their route prefixes, which KVox web does not spread. `@marinoscar/platform-web` moves to 0.1.0-next.7 (local host mode). The `shell` slice imports exactly the platform's `shell/ui`, `shell/headless` and `identity/headless`, which the `host-neutral` rule and the `kvox-web.host-neutral` conformance scan allow for that slice alone.
