Lenses, complete URL state, history and "Ask about this selection" in the graph explorer (GIC-17, #678, epic #661). Web: hidden relation types are now URL state (`relTypes` = the SHOWN relation types, like `types`), so they survive a reload and a shared link; `lens` records the lens last applied and `focus` the focused node. `from`/`to` and `pathFrom`/`pathTo` are left to the stories that write them, and pins and positions stay out of the URL. A LENS is a named bundle of seeds, the node and relation types shown, the layout and pinned positions (`explorer/lenses/`): four built-in presets (People network, Project map, Stakeholders & stance, Commitments & risks) that skip members the ontology does not have, and user lenses stored per user in the `graph` user-settings namespace under `graph.explorer.lenses` (no new table; at most 20 lenses and 300 pinned positions each, with a friendly message at the limits). The Lens menu applies, saves, renames and deletes; on a phone it is a full-screen list behind the overflow menu. History (`explorer/history/`): `useGraphExplorer` keeps a bounded stack of 50 snapshots (graph membership, seeds, filters, `as of`) and returns `undo`, `redo`, `canUndo`, `canRedo`; Ctrl/Cmd+Z and Shift+Ctrl/Cmd+Z, Back and Forward (`[` and `]`, and the browser's Back button, because a NEW focus is the only change that adds a history entry), a breadcrumb trail of the focus (full, middle-truncated or the current item by window class), an Undo snackbar after Hide and Expand on a phone, a "?" dialog listing every shortcut, and Lens, Undo and Redo actions in the command palette. "Ask about this selection": the Selection view, the edge overview and the node context menu open the host's Ask slot pre-scoped; `GraphEntityAskPanelProps` gains the optional `scope` (`GraphEntityAskScope`), `postAskMessage` and `useAskConversation` forward it, and the ask slice's `EntityAskPanel` sends it with every question. `ExplorerToolbar` gains `extraControls` and `overflowItems`; `ExplorerInspector` gains `edgeExtraActions`. API and contract: `POST /api/ask/conversations/:id/messages` takes an optional `scope: { entityIds, evidenceIds }` (at most 50 each; additive). Every id must be readable by the asker, else the whole request is a 404 with one sentence; a `sensitive` PersonFact's evidence, a personal-by-declaration type and another user's rows are never readable. The `ask.respond` job re-checks the ids when it runs, registers the entity, item or relation each one supports as a handle and names them to the agent as starting points only (never the quotes), so the agent still retrieves evidence through its tools and the graph is never a retrieval source on its own. The `graph` user-settings namespace schema, patch schema and merge accept `explorer.lenses` (`GRAPH_LENSES_MAX`, `GRAPH_LENS_PINS_MAX`).
