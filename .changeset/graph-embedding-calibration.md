The graph's embedding thresholds are per model, so `graph.embed` can run on an on-device model (#681). `@marinoscar/kvox-ai`: `KvoxEmbeddingModel` gains an optional `graphCalibration` (`KvoxGraphCalibration`: `vectorFloor`, `itemCosine`, `itemSameConfidentCosine`); `KVOX_LOCAL_EMBEDDING` records 0.83 / 0.87 / 0.95 (derived from the OpenAI numbers by headroom above each model's unrelated-pair ceiling, not yet measured on recorded vectors); `createKvoxAi` reports the entry's `provider` and `graphCalibration` on `capabilities().embeddings`. An entry that records none keeps the OpenAI baseline, so text-embedding-3-small behaves exactly as before. `@marinoscar/kvox-api`: `KvoxEmbeddingsInfo` gains optional `provider` and `graphCalibration`; `GraphEmbedder` reports the catalog entry's provider instead of a hard-coded `openai` and the resolved calibration (`DEFAULT_GRAPH_CALIBRATION`, `resolveGraphCalibration`, `GraphCalibration`, exported from `graph-extraction`); entity scoring takes the model's vector floor, item dedup (`selectCandidates`, `mapItemVerdicts`) its candidate and confident cosines; `kg.resolve` and `kg.topics_promote` read it too. Vectors of different models are still never compared. `@marinoscar/kvox-eval`: a `calibration` slice and `kvox-eval calibrate` (`--self-test`, `--dump-texts`, `--vectors`, `--json`): a labelled calibration set (entity-name and statement pairs derived from the golden meetings plus `fixtures/embedding-calibration/pairs.json`, all invented), precision and recall per threshold, the product's own decisions replayed per calibration, and the recommendation rules.
